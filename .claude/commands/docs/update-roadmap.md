# ROADMAP.md 완료 작업 동기화

`shrimp_data/tasks.json`을 1차 진실 원천으로 사용하여 `docs/ROADMAP.md`의 작업 상태와 진행률을 최신화합니다.

## 실행 모드 결정

`$ARGUMENTS`를 확인합니다:
- **자동 모드** (인자 없음): tasks.json의 completed 항목과 ROADMAP의 [TODO] 항목을 비교하여 미반영된 완료 작업을 일괄 처리합니다.
- **강제 모드** (인자 있음): 공백으로 구분된 TASK-ID(예: `TASK-010 TASK-011`)만 완료 처리합니다.

## Step 1: 현재 상태 파악

다음 두 파일을 읽습니다:

- `@docs/ROADMAP.md` — 현재 마킹 상태 파악 (`[완료]` / `[TODO]` 항목 구분)
- `@shrimp_data/tasks.json` — `status === "completed"`인 task의 `name` 필드에서 `TASK-XXX` 패턴 추출

> tasks.json이 없거나 파싱할 수 없으면: 자동 모드를 중단하고 사용자에게 완료된 TASK ID를 직접 알려달라고 요청합니다.

**처리 대상 결정:**
- 자동 모드: tasks.json에서 completed이지만 ROADMAP에서 여전히 `[TODO]`인 항목
- 강제 모드: 인자로 받은 TASK-ID 목록 (ROADMAP에 없는 ID는 건너뛰고 경고, 이미 `[완료]`이면 스킵)

처리 대상이 없으면: "이미 최신 상태입니다"를 알리고 종료합니다.

## Step 2: 각 완료 작업의 ROADMAP 마커 갱신

처리 대상 각 TASK-XXX에 대해 Edit 도구로 `docs/ROADMAP.md`를 수정합니다.

### 2-1. 작업 헤더 상태 변경

```
- **TASK-XXX: 제목** [TODO]
```
→
```
- **TASK-XXX: 제목** [완료]
```

### 2-2. `구현 사항` 섹션을 `완료 항목`으로 변환

`구현 사항` 섹션 헤더를 `완료 항목`으로 변경하고, 하위 불릿을 체크박스로 변환합니다:

```
  구현 사항
    - 항목 A
    - 항목 B
```
→
```
  완료 항목
    - [x] 항목 A
    - [x] 항목 B
```

**체크리스트 내용 보강 (선택):** tasks.json의 해당 task에 `summary` 또는 `verificationCriteria` 필드가 있으면 기존 구현 사항 불릿 대신 더 정확한 내용으로 재구성합니다. 정보가 부족하면 기존 불릿을 그대로 `[x]`로 전환합니다.

## Step 3: Phase 섹션 헤더 `(완료)` 표기 갱신

각 Phase 섹션(예: `### Phase 1-D: 핵심 기능 구현`)의 모든 TASK가 `[완료]`이면:
- 헤더에 아직 `(완료)`가 없으면 → ` (완료)` 추가
- 이미 `(완료)`가 있으면 → 변경 없음

반대로 해당 Phase에 `[TODO]` 작업이 하나라도 남아있는데 `(완료)` 표기가 있으면 → `(완료)` 제거.

## Step 4: 전체 진행률 갱신

ROADMAP의 Phase 1 / Phase 2 진행률 섹션을 재계산합니다.

**총 작업 수:**
- Phase 1: TASK-001 ~ TASK-013 + TASK-004.5 = 총 14개
- Phase 2: TASK-014 ~ TASK-018 = 총 5개

**갱신할 항목:**

### 4-1. 진행률 헤더 텍스트

```
**Phase 1 (MVP) 진행률: 약 71% (10 / 14)**
```
→ 완료 수와 % 재계산하여 교체 (% = `round(완료수 / 14 * 100)`)

### 4-2. 완료/진행 중/대기 요약 3줄

```
- 완료: 프로젝트 문서화, UI 프레임워크 설정, ...
- 진행 중: 없음
- 대기: 실제 데이터 연결(ISR), PDF 다운로드 개선, ...
```

완료된 TASK의 짧은 설명을 쉼표로 이어 `완료:` 줄에 나열합니다. `대기:` 줄에는 아직 `[TODO]`인 TASK 설명을 나열합니다.

### 4-3. ASCII 진행 바 갱신

20칸 기준으로 `▓`(완료)와 `░`(미완료) 비율을 재구성합니다:
- `▓` 칸 수 = `floor(완료수 / 전체수 * 20)` (소수점 버림)
- 나머지 칸은 `░`

```
Phase 1 (MVP)        ▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░  71%  (TASK-001 ~ TASK-013, TASK-004.5)
Phase 2 (기능 확장)  ░░░░░░░░░░░░░░░░░░░░   0%  (TASK-014 ~ TASK-018)
```

퍼센트 숫자와 바를 갱신합니다.

## Step 5: 검증 및 사용자 보고

아래 순서로 마무리합니다:

1. `git diff --stat docs/ROADMAP.md` Bash 명령으로 변경된 라인 수를 확인합니다.
2. 다음 형식으로 한국어 요약을 출력합니다:

```
✅ ROADMAP.md 동기화 완료

**새로 [완료] 마킹된 작업:**
- TASK-XXX: ...
- TASK-YYY: ...

**진행률 갱신:**
- Phase 1 (MVP): 71% (10/14) → N% (X/14)

**검토 권장:**
git diff docs/ROADMAP.md 로 변경 사항을 확인한 뒤 직접 커밋해주세요.
```

변경 사항이 없었다면: "ROADMAP.md는 이미 최신 상태입니다. 반영할 미완료 항목이 없습니다."를 출력하고 종료합니다.
